# SvelteKit への移行計画

作成 2026-09-23。対象 `kuhaku.caprer.co.jp`。

## なぜやるか / やらない理由もここに書く

目的は**他サービス（LaneDuel 等）と構成を揃えること**の一点である。機能的な要求は無い。
このサイトは Worker スクリプトを持たない純静的配信で、動的要素は PostHog と
`<details>` の開閉だけ。SvelteKit の実行時機能を必要としていない。

外部レビュー（Codex）と実装側の見立ては一致して「**一貫性のためだけなら見合わない**」だった。
工数 6〜9日、うち大半は「保証が壊れていないことの証明」に消える。
そのうえで、1人で6サービスを保守する文脈切替コストを理由に**実施を決定**した。
この判断の前提が変わったら（例: 保守頻度がさらに下がる）、中断してよい。

**やらないこと**: 内容の追加検証。2026-09-23 に20件で凍結済み。移行は表示層の話であり、
判定・観測値・文面は一字も変えない。

## 不変条件（壊したら失敗）

| # | 不変条件 | 現在の担保 | 移行後の担保 |
|---|---|---|---|
| 1 | 第三者が **node 無しで**公開値を検算できる | `./run.sh verify`（Python標準ライブラリのみ） | **変更しない。** Python が証拠・算出・判定・公開ラベル・CSV/JSON を所有する |
| 2 | 配信される文面が検査を通っている | `lint_copy.py` が生成HTMLを読む | prerender 後のHTMLを読む。**検査した成果物をそのまま配信する**（再ビルドしない） |
| 3 | 「何を公開したか」の履歴が残る | 生成HTMLを git にコミット | 同左を維持する（ビルド成果物化しない）。README がこの目的を明記している |
| 4 | `.claude/` が公開されない | `site/public/.assetsignore` | **実際の配信ルートに置き直す。** `.assetsignore` は許可リストではない |
| 5 | `workers_dev:false` / 独自ドメイン | `site/wrangler.jsonc` | Worker 名 `kuhaku-zukan`、route `kuhaku.caprer.co.jp` custom_domain、zone `caprer.co.jp` を維持 |
| 6 | 主張が変わっていない | （無かった） | **`site/parity.py`**。移行前の指紋と比較する |
| 7 | 404 の挙動 | `not_found_handling: 404-page` | SPA の全捕捉にしない |

## 安全網（先に用意した）

`site/parity.py` — 公開HTMLから「主張の指紋」を採る。

- 概念カードの数と id、判定クラス、カード内の全数値、改訂ID、体裁を除いた本文ハッシュ
- ページ全体の改訂ID・外部リンク・必須文言（正規表現で保持。表記ゆれで空振りした経緯あり）

検証済み: 概念削除・数値改変・改訂ID欠落・必須文言欠落・外部リンク欠落を**7件すべて検知**。
CSS差し替え・タグ種別変更・空白正規化では**誤検知ゼロ**。

基準は `site/parity-baseline.json`（移行前の版で採取済み）。

## 段階

### 第1段階 — データ契約の切り出し（完了）

`pipeline/viewmodel.py` → `data/viewmodel.json`。表示層はこれ**だけ**を読む。
公開ラベル・欠測と0の区別・訂正種別・採用基準ラベルは Python 側で解決済みで、
Svelte には解釈を持たせない。

`site/parity.py --contract` が「公開物の数値・改訂ID・概念がすべて契約から導けるか」を検査する。
**これが通ることが `build_site.py` を捨てる条件**。作成時に実際に3件の欠落が見つかった:
判定時に読んだ英語版の改訂ID（観測した版と違う）、判定ID、採用基準。

### 第2段階 — 足場（ほぼ完了・ビルドが1点未解決）

`web/` に SvelteKit + adapter-cloudflare 5.1.0 + Tailwind v4 + Biome + Vitest + pnpm。
`pnpm check` は 313ファイル・エラー0・警告0。表示層は `data/viewmodel.json` だけを読む
（`+page.server.ts` で事前生成時に一度読む）。

**LaneDuel との意図的な相違**: LaneDuel は Pages モード（`pages_build_output_dir`）だが、
空白図鑑は独自ドメインを wrangler の route で持っている。Pages にすると紐付けが設定ファイルの
外（ダッシュボード）に出て**不変条件⑤を壊す**ため、adapter-cloudflare のまま
**Workers モード**（`main` + `[assets]`）にした。

**判明した問題（不変条件④に直撃）**: adapter-cloudflare は出力先に**自前の `.assetsignore` を
生成する**（中身は `_worker.js` / `_routes.json` / `_headers` / `_redirects` の4つだけ）。
`.claude/` は含まれない。**`.assetsignore` に頼る方式は使えない。**
→ 配信物の**一覧そのものを検査**する方式に変える（第5段階）。

**未解決**: `pnpm build` が sandbox 内で `listen EPERM 127.0.0.1` で落ちる。
アダプタが workerd を起動するため。sandbox 外なら通る見込みだが、第三者コードを
sandbox 外で走らせる判断は本人に委ねる。CI（GitHub Actions）では制約が無いので通るはず。

### 第3段階 — 部品への移植と UI 修正（1〜2日）

作り直すので、UI の不具合はこの段で同時に直す（二度手間を避ける）。実測済みの8点:

| # | 問題 | 実測 | 対応 |
|---|---|---|---|
| 1 | 版面が広い | 47.5全角字/行（`palt` で実質さらに増） | 本文は約40字/行へ。表は別幅 |
| 2 | ライトモードの弱色 | `#6E6E75` on `#EFEDE7` = 4.32:1 | 4.5:1 以上へ |
| 3 | 意味を運ぶ罫線が薄い | `--kei` = 1.47:1 | 未検証の破線・比較できないの斜線は 3:1 以上へ |
| 4 | ドット符号化が数えられない | 折り返し＋60超で `…` 切り捨て | **数値を主、図を従に**。切り捨てで嘘をつかない |
| 5 | ダッシュ字形の混用 | 同じ「データなし」に `–` と `—` | 1種に統一 |
| 6 | 等幅の誤用 | 探索記録の日本語記事名が等幅 | 等幅は revid・英語タイトルなど識別子のみ |
| 7 | カード境界が弱い | 番号と余白のみ | 明示的な境界を与える |
| 8 | ヒーローの数字が直書き | `build_site.py:683` の「2件」 | 導出するか、語りの数字と明示する |

**残すもの**: 判定チップの塗りの濃さによる序列、色に頼らない符号化（斜線・破線）、
見出し明朝／本文ゴシック、単位に忠実な図示、「—は候補が無かった」の注記。
これらは情報設計として正しく、移行で失いやすい。

### 第4段階 — ゲートの作り直し（1〜2日）

- `lint_copy.py`: 位置引数の経路が数値照合・構造検査を飛ばす件は修正済み（`100adc9`）。
  prerender 後のHTMLを**完全な検査対象**として扱う経路を足す
- `check_numbers()` は TOML の文章しか見ていない。**描画された表の数値**を概念×指標で照合する
- CI の「再生成一致」検査は、HTMLが非追跡になると成立しない → **データ層の一致検査**に置き換え、
  HTMLは第3不変条件によりコミットし続ける
- 配信順序: Python の出力と検証 → フロント構築 → Python が最終HTMLとダウンロード物を検査 →
  **その検査済み成果物を配信**（配信時に再ビルドしない）

### 第5段階 — 配信と検証（1〜2日）

- 意図的に壊した文面・誤った描画値がゲートで落ちることを試験する
- 配信後: 公開すべきものが 200、`.claude/` 配下の**個別ファイル**と `.assetsignore` が非公開、
  配信内容が検査した成果物と一致すること（ディレクトリURLの404だけでは不十分）
- 失敗時の戻し手順を書く
